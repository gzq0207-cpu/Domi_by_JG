# 文档目录中的拖拽移动

实现和验证日期：2026-10-20。

在文档库右侧目录中，按住 Markdown、PDF 或 Word 文件行，拖到另一个文件夹上即可移动实际文件。目标文件夹会高亮，悬停约 650 毫秒会展开折叠目录。拖到“全部文档”可移回资料库根目录，再次拖动可移回原文件夹。

移动前会保存当前文档的编辑内容。移动成功后，目录局部更新，当前打开的文档加载新路径；新旧搜索索引同步切换，阅读评论继续关联原文，资料库文章路径、文档索引和人物材料记录也会更新。移动操作由目录后台线程执行，不以全库扫描作为完成条件。

目标位置存在同名文件时，操作失败并提示，两个原文件都保留。放回原文件夹不会产生文件移动。文件在其他应用中发生变化、目标越出资料库、目标是外部目录链接等情况也会拒绝移动。复制或关联记录更新失败时保留原文件，并回退已创建的目标副本及关联记录。

单篇 Markdown 移动时，会调整正文中常规 Markdown 图片、附件和参考式链接的相对路径，使其继续指向原文件；代码示例、网页链接和纯章节锚点保留原样。其他文档和历史对话中写死的旧文件路径不会进行全库文本替换，移动后这类链接可能需要重新选择来源。PDF、DOCX、DOC 的文件字节保持一致。

项目主页、人物主页、带有主题研究身份的研究笔记和根目录待办入口由对应工作区管理，不能作为普通材料单独移动。文件夹本身的整目录拖动和多选批量移动不属于本次功能。

## 验证

96 项相关测试通过，涵盖目录线程、文件移动、增量目录、搜索、阅读评论、主题研究、镜像、查询快照等。生产 Electron 界面在 4,000 篇文档、80 个文件夹的临时资料库中通过 14 组场景，其中包括原生鼠标拖拽、长目录滚动、未保存内容、移到根目录后再移回、同名冲突以及移动不触发全量刷新。

`npm run build`、相关 Electron 源文件语法检查和 `git diff --check` 通过。机器可读界面结果、截图和测试日志在本地 `output/document-library-performance/` 目录。

源码和本地生产构建已更新。从当前项目重新启动 Domi 后生效；独立安装的发布包需重新打包更新。
