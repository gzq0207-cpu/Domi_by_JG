# 新建文件与文件夹的响应性能优化

检查和验证日期：2026-10-20。修改位于 Domi1 本地工作区，前端生产构建已更新。

## 根因与改动

原先 `document-library:create` 在 Electron 主进程同步创建条目后，强制扫描整个文档库，再把完整目录树返回界面；这次刷新也会强制触发搜索索引。目录扫描逐文件检查元数据，部分 Markdown 还会读取文件头。文件越多，主进程连续占用的时间越长。

现在 `electron/document-library-service.cjs` 和 `electron/document-library-worker.cjs` 将初始化、目录扫描、文件创建交给独立线程。并发的相同刷新请求合并，目录快照保留 60 秒缓存；新增条目直接返回文件节点。Markdown 创建后只向搜索服务提交新文件，创建空目录不触发搜索索引。目录扫描中的中文自然排序复用一个 `Intl.Collator`，避免每次比较重复构造排序器。

界面原先把新建名称存放在大型 `App` 组件的状态中，每次键入都会引起整页渲染和可见文件树重建。现在名称由表单原生输入框维护，提交时读取；`DocumentLibraryTree` 独立缓存，只有目录、展开状态、选中项等相关属性变化时才重建。`document-library-tree.ts` 只复制新增节点的祖先分支，保持其他文件夹对象不变，并维持文件夹优先、中文自然排序和计数。

新建完成后会废弃更早的刷新响应，防止旧目录快照盖掉新文件；切换资料库时也不会把旧资料库的成功响应插入新目录。某个子目录在扫描时消失或不可读，只标记本次扫描不完整，其余可读文档仍然显示。

文件监听还有一条延迟发生的工作链：变动几秒后触发飞书镜像。过去镜像在主进程同步遍历目录、读取文件并计算哈希。现在运行时目录遍历和文件读取改用异步操作，哈希改为流式读取；普通笔记和隐藏备份不再触发不相关的镜像扫描。原有镜像范围、内容完整性检查和账本去重语义保留。验证使用模拟飞书服务，没有向真实飞书写入。

## 测量

Windows，Node v24.19.0；临时资料库包含 4,000 篇 Markdown、80 个文件夹。修改前代码取自本次改动前的 Git HEAD，修改后代码取当前工作区；每组 5 次，以下为中位数。

| 操作 | 修改前 | 修改后 |
|---|---:|---:|
| 全量目录扫描 | 1,049 ms | 405 ms |
| 新建 Markdown 的后台返回 | 718 ms | 10.1 ms |

后台返回测量包含创建与返回目录信息所需的时间，不包含界面绘制、编辑器首次加载、搜索索引和云盘同步争用。修改后的全量扫描仍需读取目录，但运行于后台线程，不再同步占用 Electron 主进程。测量结果用于说明这条操作链的开销变化，不代表所有机器或所有操作的固定耗时。

生产构建的 Electron 界面测试也使用 4,000 篇文档、真实 IPC、真实目录后台线程和临时文件系统，实测新增文件夹、新增 Markdown 的后台调用分别约 3.5 ms 和 3.7 ms。输入事件处理测量不包含隐藏测试窗口的绘制延迟，不用它推断实际显示帧率。

机器可读结果位于 `output/document-library-performance/benchmark-results.json` 和 `output/document-library-performance/ui-results.json`；界面截图为同目录下的 `electron-library.png`。这些文件是本地验证产物，不纳入源码发布。

## 验证

71 项针对性测试通过，覆盖文档目录、后台线程、增量插入、搜索索引、文档路径、侧栏导航、镜像、查询快照与日报。生产 Electron 界面验证通过 9 组场景：嵌套文件夹与 Markdown 连续创建、新文件自动打开、新建不触发全量刷新、旧刷新不能覆盖新条目、重复命名保留原文、取消后重置名称、读取外部新增文件、跨 80 个目录搜索、无 renderer 异常。

`npm run build` 已通过（隐私规则单测、TypeScript 和 Vite）；相关 Electron 文件语法检查及 `git diff --check` 通过。`npm run test:document-library` 可重新构建并运行本次核心测试和 Electron 界面验证；需使用支持 `--experimental-strip-types` 的 Node，本次使用随 Codex 安装的 Node v24。

全仓检查并非全部通过：原有 `renderer-resilience.test.cjs` 仍查找源码中已不存在的“domi 状态”面板，修改前源码也没有对应标记；全仓隐私扫描还命中既有、已被 Git 跟踪的资料库文章中的邮箱、域名和疑似凭据文本。此次未清理或改写资料库内容。镜像测试中另有一个固定域名期望与模拟服务域名不一致，已改成严格核对账本记录的目标 URL。

## 生效范围

源码和本地前端构建已更新。从本项目重新启动 Domi 后加载本次修改。已运行的旧 Electron 进程需要完全退出后重新启动；独立安装的发布包不会因为源码目录更新而自动替换。
