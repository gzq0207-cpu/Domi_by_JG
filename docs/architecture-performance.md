# 架构与交互响应修复

2026-10-20，针对聊天历史重绘、运行期资料库阻塞、搜索切库竞态、来源哈希和缓存失效的修复。

## 运行期职责

`App` 通过稳定的 `onOpenMessageDocument` 入口打开消息中的文档，ref 转发到最新处理函数。输入与流式更新不再因为回调引用变化而使所有历史 `MessageContent` 重新解析 Markdown。原有消息内容变化和引用审计变化仍正常更新。

`LocalRepositoryService` 将实体目录解析、动态查询、数据库快照、编辑、预览、删除、分类及 Markdown 落盘交给 `local-repository-worker.cjs`。worker 复用连接，同一队列内串行执行，切换数据库时关闭旧连接。schema 和迁移在连接初始化时执行。集成层继续维护缓存与落盘队列；mutationId、expectedUpdatedAt、事务、目录边界和重试语义保留。

`ResearchService` 将主题研究、来源注册、评论与版本核验交给 `research-worker.cjs`。每个请求传递当次已授权的外部路径，worker 仍检查真实路径；外部路径撤权后不能继续读取。PDF 打开时的来源指纹也在 worker 中计算。完整 SHA-256 校验采用 256 KiB 缓冲读取，避免为计算哈希一次分配整份大文件。

两类服务共享 `BackgroundService` 的请求关联、错误收敛、超时和关闭机制。默认等待期限 30 秒。超时不会自动重放或强制终止写入，未确认的操作继续计入繁忙状态，直到 worker 回执或退出。关闭请求排在已有任务后面，数据库关闭后才确认退出。修改资料连接、安装更新和退出时考虑这些后台操作，避免切换时仍有未确认的保存。

显式本地转飞书迁移继续使用既有专用链路；WorkbenchStateStore 的工作台状态存储也未迁入该服务。本次迁移针对高频资料库操作与研究材料校验。

## 搜索和缓存的一致性

搜索 worker 的每个根目录有 epoch。完整扫描、单文件更新、Word/PDF 提取、语义查询和 embedding batch 均检查所属 epoch；检查覆盖异步等待后及写入、回复之前。A → B → A 的往返也会使第一轮 A 的任务失效。

搜索宿主在切库时立即结束旧请求，并忽略迟到回复。设置保存也会撤销旧查询。全文和语义 SQL 显式按 root_path 过滤，避免依靠后续全量扫描才清理旧数据。

ServiceCoordinator 的 invalidate 增加缓存 generation，并脱离旧 in-flight 请求。旧请求不能恢复 TTL、覆盖新值、清空新请求或为新配置打开熔断器；同代请求仍合并。

## 验证方法

使用支持 node:sqlite 的 Node（本机验证为 v24.19.0）：

```powershell
npm run test:architecture
```

该入口先构建，再运行后台服务、并发版本和既有集成测试，随后进行生产 renderer 与真实 Electron IPC 验证。新增的后台和搜索并发测试也接入标准 check 的 postcheck。

后台专项覆盖：数据库持锁时调用线程仍响应、连接复用、幂等编辑与旧版本冲突、后台落盘、超时写入的迟到确认、worker 异常后恢复、关闭队列、外部路径撤权、评论重启恢复、大文件哈希，以及 stat、Word 提取、往返切库、语义推理与向量填充期间的旧任务隔离。

renderer 验证使用生产构建、headless Chromium、模拟 bridge 和相同输入文本；React 提交观察器确认输入没有改变历史消息回调。真实 Electron IPC 测试使用实际 main.cjs / preload 和后台服务，在临时目录验证查询、编辑、幂等重试、实体预览、附件归档、PDF 指纹、评论和正常退出；启动联网集成被测试夹具暂停。

## 本机测量

每条回答 588 字符，含段落、加粗和表格；输入相同文本，30 ms 键入间隔，预热后测量。下表为整段输入测量区间的 renderer TaskDuration 增量，不是一次按键延迟或实际显示帧率。

| 历史对话 | 修复前 | 修复后 | 修复前超过 50 ms 的长任务 | 修复后 |
|---|---:|---:|---:|---:|
| 1 轮 | 338 ms | 208 ms | 0 | 0 |
| 20 轮 | 1,225 ms | 244 ms | 0 | 0 |
| 60 轮 | 3,613 ms | 307 ms | 41 | 0 |

60 轮样本另两次复测约为 339、420 ms，均为 0 次长任务；测量有环境波动，不能承诺所有机器和内容都保持同样耗时。

另一个线程持有数据库写锁 800 ms 时，修复前 10 ms 心跳延迟到约 878 ms；迁移后约 12 ms，数据库响应仍等待约 825 ms。变化在于主线程保持响应，锁等待本身没有消失。

128 MiB 来源样本的三次完整校验，修复前调用线程心跳延迟约 181–245 ms；迁移后约 14–25 ms，后台完整校验耗时仍约 203–215 ms。样本仅测试来源校验，不测试 PDF 格式解析。

原始结果位于本地 `output/architecture-performance/`，修复前审查和复现数据位于 `output/architecture-review-2026-10-20/`。目录均为本机验证产物，不纳入发布源码。
